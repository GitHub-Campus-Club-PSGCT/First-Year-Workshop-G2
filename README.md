# Git & GitHub Workshop

> Welcome to the Git & GitHub workshop :)

If you've never used Git before, don't worry. That's kind of the whole point of this workshop.

We'll go through the basics, mess around with some code, break a few things, and hopefully leave knowing why Git is actually useful instead of just being that thing everyone tells you to learn.

---

## What we'll be doing

During the hands-on session, we'll go through things like:

- Creating and switching between branches
- Making changes to files
- Staging and committing changes
- Pushing changes to GitHub
- Opening Pull Requests
- Reviewing changes
- Merging branches
- Dealing with merge conflicts

The repository itself is intentionally simple.

**The code isn't the point. The workflow is.**

---

## Git at a glance

The basic Git workflow looks something like this:

**Make changes → Stage → Commit → Push**

A few things you'll see along the way:

- **Stage**: Tell Git which changes you want to include
- **Commit**: Save those changes to your Git history
- **Push**: Send your commits to GitHub
- **Pull**: Bring changes from GitHub into your local repository
- **Branch**: Create a separate line of development
- **Pull Request**: Ask for your changes to be reviewed and merged

We'll be using the **VS Code interface** for most of this, so you don't need to memorise a bunch of commands.

---

## Working with GitHub

Git becomes a lot more useful once you're working with other people.

For the collaboration part, you'll work with your own fork of this repository.

The general flow is:

**Fork → Make changes → Commit → Push → Pull Request → Merge**

This lets everyone work on their own copy while still contributing back to the original repository.

And yes, there will probably be a merge conflict at some point.

That's intentional. :)

Pull Requests submitted to this repository are automatically merged, so once you've gone through the workflow, you can see your changes make their way into the main repository without someone sitting here manually merging everyone's PRs.

---

## Don't worry if Git feels weird

Git can be confusing when you first start using it.

You'll probably run into things that make absolutely no sense the first time you see them. That's normal.

Ask questions, try things out, and don't be afraid of breaking something. That's how you actually start understanding what's going on.

And if something goes wrong, **that's also part of the workshop.**

---

## What's next?

You definitely don't need to become a Git expert today.

As you work on projects, participate in clubs, build stuff with friends, or eventually work on larger codebases, Git and GitHub will start becoming part of your normal workflow.

For now, just get comfortable with the basics and don't overthink it.

You can also check out the [GitHub Student Developer Pack](https://education.github.com/pack) to see what tools and benefits are available to you as a student.

And if you get stuck later, there's always the [GitHub Docs](https://docs.github.com/) or, you know, your seniors :)
